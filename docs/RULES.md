# 规则设置

适用版本：0.1.5。14 条内置规则默认启用，命中后默认「替换」。每条规则都可以改为「阻断」或关闭；自定义规则支持新增、编辑和删除。

## 选择处理方式

打开 App 左侧「规则」，在对应行修改「命中后」或「状态」。出现「已保存，从下一条请求开始生效」后，普通 API 和 WorkBuddy 原生 HTTPS 入口都会使用新设置，无需重启。

| 设置 | 发生什么 |
| --- | --- |
| 替换 | 将命中的片段换成本请求的代号，再继续请求 |
| 阻断 | 命中时停止整条请求，不发送给模型服务 |
| 关闭 | 此规则不再检查新请求；其他启用规则仍然生效 |

一条请求命中多条规则时，只要其中一条设置为「阻断」，就阻断整条请求。全部为「替换」时进行替换；没有命中则放行。修改不会追溯改变已完成或正在处理的请求。

正常有效的 Token 仍可能是敏感信息。「识别为凭据」与「是否阻断」是两项独立判断。粘贴在消息正文里的 curl、Cookie、Bearer 或 JWT 按规则处理；WorkBuddy 连接其官方服务时实际携带的认证 Header 保持原样，不参与正文替换。

## 新增自定义规则

1. 点击「新增规则」，填写名称。
2. 选择「固定文本」或「正则表达式」，填写匹配内容。
3. 选择是否忽略大小写，以及「替换」或「阻断」。
4. 如需检查，展开「测试这条规则」，输入一段自己的测试文本，点击测试。
5. 点击「保存规则」。新规则出现在「自定义」列表，并用于下一条请求。

固定文本适合内部项目代号、专属标识等明确值；正则适合具有固定格式的数据。例如 `INTERNAL-[0-9]{6}` 匹配以 `INTERNAL-` 开头、后接六位数字的片段。直接填写表达式，不添加 `/.../g` 包装。匹配会覆盖每处完整命中，捕获组不定义单独替换内容。

列表中的编辑按钮可修改已有自定义规则；删除按钮会先显示确认操作。内置规则可以关闭或改变动作，不能删除或修改其检测表达式。这样应用更新内置检测能力时，仍能保留本机动作设置。

测试只检查正在编辑的这一条规则，不保存设置、不调用模型、不写入请求记录；保存后，真实请求会同时应用全部启用规则。内置正反例与批量验证留在仓库测试中，不占用日常界面。

## 内置规则

以下规则初始动作均为「替换」。规则名称左侧可展开查看范围和边界。

| 规则 | 检测内容 |
| --- | --- |
| 服务器私钥 | PEM、RSA、EC、DSA、OpenSSH、PGP 等私钥块 |
| 明文私钥与签名密钥 | 明确的 private_key、secret_key、signing_key、私钥字段 |
| API Key 与开发平台令牌 | 常见模型、GitHub 令牌前缀及 api_key、client_secret 等字段 |
| 云服务访问密钥 | AWS、阿里云、腾讯云密钥前缀及明确的访问密钥字段 |
| 服务器与数据库连接凭据 | 带认证信息的数据库、SSH、SFTP、HTTP 等连接字符串 |
| 账号密码 | password、passwd、pwd、密码、口令字段的值 |
| OAuth Token | 消息正文中的 Bearer、access_token、refresh_token 等 |
| JWT / JWE 令牌 | 具有 JSON 头部特征的三段 JWT 或五段 JWE |
| BIP39 助记词 | 十种字典、12 / 15 / 18 / 21 / 24 词与校验 |
| 明确标注的助记词 | 助记词、seed phrase、recovery phrase、mnemonic 字段 |
| 邮箱 | 常见邮箱地址 |
| 中国大陆手机号 | 11 位号码、+86 前缀及常见分隔写法 |
| 中国居民身份证 | 18 位证件的地区、出生日期与末位格式 |
| 账号名称 | username、login、account、用户名、账号等明确字段 |

内置规则由应用随版本提供，不需要从服务器下载；目前没有远程规则订阅或热更新服务。BIP39 来源与许可见 [字典说明](BIP39-WORDLISTS.md)。

## 保存与错误处理

规则保存在 Electron 应用数据目录的 `rule-settings.json`；macOS 当前为 `~/Library/Application Support/AI Privacy Gateway/rule-settings.json`，Windows 为系统对应的应用数据目录。内置动作覆盖与自定义定义分开保存，重启后恢复。自定义匹配文本可能包含内部标识，应按本地配置资料保管。请求原文、测试输入、映射与记录仍只在内存中。

- 最多 100 条自定义规则；名称 1–60 字符，表达式 1–512 字符，测试输入最多 12,000 字符。
- 正则语法无效时不能保存。空匹配、超过 2,000 处命中或匹配超过 100 ms 时停止本次检查，不将未完成检查的正文发送出去。简化表达式或关闭对应规则后重试。
- 保存失败时提示错误，原配置继续有效；配置文件损坏时暂停请求检查并提示修复，避免默默丢失已设置的阻断规则。
- 已打开的旧编辑内容与新配置冲突时，拒绝覆盖并提示重新编辑。

## 查看结果与边界

「记录」展示命中类型、处理动作和请求状态。详情额外展示命中规则的名称、内置 / 自定义来源、各自动作和配置版本。被阻断的详情提供「修改规则的处理动作」入口。原生请求成功时，详情展示实际发送正文校验及认证保持状态。

WorkBuddy 对主动阻断目前显示通用服务错误；具体原因在网关记录中。修改动作后可直接在 WorkBuddy 重试。原生内容阻断使用 HTTP 422，避免以 401 / 403 伪装登录失效；真实上游的认证错误仍按上游响应处理。

替换不保证模型完成依赖真实凭据的操作；模型收到代号后无法用原 Token 登录或执行业务请求。当前 WorkBuddy 原生入口和 SSE 不恢复响应代号。规则检测也不等于语义分类，姓名、地址、业务机密推断、编码混淆与跨字段拆分尚未完整覆盖。

本轮测试证据见 [0.1.5 交付与验证](ITERATION-0.1.5.md)，接入步骤见 [WorkBuddy 使用指南](USAGE.md)。
