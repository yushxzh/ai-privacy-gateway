## 产品目标

让个人开发者和 AI 重度用户继续使用原来的客户端、登录、模型与订阅，在模型请求离开本机前检查敏感内容，并自行决定替换、阻断或关闭相应规则。

产品价值由三件事共同证明：**原有使用方式能继续、敏感内容按选择得到处理、处理结果可以核对。** 自定义 API 请求成功、代理进程启动或增加平台说明页，都不能单独证明目标达成。

### 用户与主要任务

| 用户 | 已有使用方式 | 希望完成的事 |
| --- | --- | --- |
| 使用官方会员的个人开发者 | Codex、Claude Code、WorkBuddy 等原客户端与订阅 | 开启保护后继续原任务，无需另买 API 或重复填写认证资料 |
| 使用 Coding Plan / 自备 API 的开发者 | 已配置的套餐入口、API Key 或本地模型 | 保留原来源和计费方式，让请求经过本地检测 |
| 技术负责人、安全工程师 | 团队成员各自使用 AI 应用 | 先验证个人产品，再获得统一规则、设备和审计管理能力 |

### 产品与商业路线

免费开源核心 → 个人持续使用 → 团队主动采用 → 按真实需求建设企业管理能力。

个人阶段优先投入安装接入、检测质量、任务兼容性和恢复能力。企业候选范围为统一策略、设备、权限、元数据审计及私有部署，尚未确定收费功能或商业排期。当前公开核心保持 MIT 许可。

### 三种接入分别验收

| 使用方式 | 身份与额度 | 产品要求 |
| --- | --- | --- |
| 原生登录 / 会员 | 原客户端管理本人登录、续期与权益 | 默认主线；不静默切换为其他服务或独立 API 计费 |
| 第三方 Coding Plan | 用户已经购买的套餐及其允许的端点 | 保留该套餐的原认证和用途，不能只凭模型名称推断额度归属 |
| 自备 API / 本地模型 | 已有 API Key、API 余额或本机推理服务 | 提供兼容入口与配置说明，作为独立能力保留 |

HTTPS 解密是接入手段之一。安装信任证书或筛选域名不能替代协议适配，也不能证明客户端所有模型、辅助调用和工具流量都已接受检查。

## 优先级规则

| 等级 | 定义 | 排序依据 |
| --- | --- | --- |
| **P0 · 必需** | 下一次双平台预览版的基本交付条件 | 直接决定能否接入、是否正确处理内容、是否能恢复，以及用户能否看懂结果 |
| **P1 · 核心增强** | 从文本 MVP 走向日常原订阅使用 | 完整 Agent 任务、主要客户端、检测质量、会话与响应处理 |
| **P2 · 扩展** | 在主路径稳定后扩大覆盖与使用深度 | 更多客户端、高级本地能力、开发者集成和灵活策略 |
| **P3 · 后置** | 需要新增使用需求或商业条件支持 | 独立新入口、多模态、团队和企业产品 |

同级先处理正确性与恢复问题，再处理体验与新增数量。已完成的 P0 仍列入清单，作为后续版本必须保持的行为；「暂缓」不等于取消，也不降低需求本身的重要性。里程碑使用 M0–M5 编号，与 P0–P3 需求等级分开。

### 状态规则

- **已验证**：限定范围有实现，且有相应测试或真机证据；不推及未测系统与客户端。
- **部分实现**：已完成一部分，仍有明确缺口或必要验收未完成。
- **仅预留**：只有类型、接口或说明，没有可用功能。
- **未实现**：当前没有可交付实现。
- **暂缓**：需求保留，按当前决定暂停推进。
- **已取消**：有明确取消决定，不进入当前路线图。

## 关键功能要求

本节定义目标行为。是否已实现以需求清单的状态列为准；尚未实现的验收条件不会因写入本文而变成当前产品能力。

### 接入与恢复（REQ-001–005、REQ-011）

1. **开启前检查**：识别客户端和适用版本，确认代理运行时、端口和证书条件。界面说明需要的系统授权及客户端重启，不要求手工准备实验参数。
2. **保留原配置**：只修改接入所需字段，记录可恢复的原值；模型 URL、原认证与额度不因原生接入而改变。用户已有其他代理时保留其恢复资料。
3. **系统授权与生效**：每台设备独立生成证书。授权取消、端口冲突或客户端未退出时，显示具体原因并保留重试 / 恢复操作，不强杀未保存的任务。
4. **确认真实请求**：本地监听、配置完成、真实请求成功分别表达。检查本地连接不自动发送收费模型请求；首个真实请求完成后才更新验证时间。
5. **停止与恢复**：正常停止先恢复客户端连接，再停止代理；用户后来选择的另一代理不能被旧备份覆盖。恢复失败时保持错误可见，避免以退出掩盖未恢复状态。
6. **异常与卸载**：崩溃后重新启动可检测遗留接入；普通停止可以保留证书，完全移除功能应只撤销本产品对应的信任与私钥。

当前一键状态为「未开启 → 正在接入 → 已配置 · 等待请求 → 已验证 → 正在恢复 → 未开启」，各步骤可进入「需要处理」。已验证只说明最近一条符合要求的请求已完成；断连、代理退出或配置改变后不能继续保留旧的验证结论。

**当前缺口**：全新 macOS 用户的系统授权、Windows 真机、完整证书撤销和卸载仍需验收；崩溃时不能保证即时恢复。停止操作不是证书卸载。

### 检测、规则与动作（REQ-006–008、REQ-021–023、REQ-025）

内置规则由维护者提供，自定义规则由用户补充。当前使用厂商前缀、明确字段、格式和校验算法组合，不承诺一条通用正则可以识别所有随机密钥。维护者可随应用版本补充规则；未来独立规则包只下发规则，不把原文送往服务器检测。

| 情况 | 期望行为 |
| --- | --- |
| 初始安装命中内置凭据 / PII | 默认替换，保留用户修改动作的能力 |
| 正文中出现实际有效的 Token | 当作敏感内容识别，按该规则动作处理；不能只因有效就固定阻断 |
| 调用模型所需的认证 Header | 保持原服务认证，不把它当作 Prompt 做替换 |
| 命中多条规则 | 任一启用规则要求阻断，则整条请求阻断；否则合并替换范围，结果可解释 |
| 关闭一条规则 | 后续请求不再使用它，其他规则继续生效；不改变已有请求记录 |
| 自定义规则保存成功 | 下一条请求使用新版本，两类入口一致；处理中请求保持自身版本 |
| 正则无效、超时或命中过量 | 明确失败，停止对应请求；不能卡死 App 或静默放行 |
| 规则文件损坏 / 写入失败 | 展示修复信息；写入失败保持旧配置，损坏配置不能被当作空规则集继续放行 |

自定义规则首版属性包括名称、固定文本 / 正则、匹配内容、忽略大小写、启用状态和动作。内置规则可改动作或关闭，其定义由维护者管理。编辑器测试只在本机执行，不产生真实网关记录，不修改运行设置，也不调用云端模型。

语义分类恢复排期后，先确定类别与独立样本，再选择本地模型。必须定义分类命中的处理范围：可以定位片段时替换片段，只有段落级判断时明确整段动作；不能只展示一个分类标签却没有真实策略。模型下载、占用与关闭方式须可见，普通规则模式不依赖模型；模型不可用时，已启用的语义保护不能静默消失。

### 请求覆盖、映射与任务兼容（REQ-005、REQ-016–020）

完整模型请求不止输入框文字，还可能包含系统说明、历史消息、文件内容、工具定义、工具参数及工具结果。需逐客户端确认最终请求形成的位置和实际出口。

- 对声明受保护的模型端点，在正文检查完成前不得开始发送正文。解析失败、检查服务失联或协议改变应停止并说明原因。
- 未适配的独立上传、云端任务、遥测或工具直接联网，不计入受保护统计；不能把域名匹配等同于全部内容覆盖。
- 原生适配应优先使用可保留原登录的配置或代理入口。若实际改用了其他供应商或 API 计费，需要用户主动选择，并标记为另一种接入方式。
- 会话映射必须有隔离范围、容量和失效条件。只有本会话生成的映射可恢复，不从模型输出臆造原值，也不从其他会话取值。
- 响应恢复按显示文本、工具参数和协议标识分别处理。流式代号跨片段仍能正确恢复；取消和失败后释放缓冲与映射。
- 本地工具执行若需要真实文件路径或凭据，必须设计受限的字段恢复与执行边界；不能把恢复后的敏感工具结果原样再次交给云端。
- 替换后的任务仍须完成读文件、修改、验证、继续对话等实际步骤。删去工具声明或关闭工具能力后完成普通文本回复，不算完整 Agent 验收。

当前 WorkBuddy 原生适配会保留部分工具结构并检查相关文本，但尚无完整工具循环、流式恢复和跨轮稳定映射的验收证据。普通 API 入口仍明确拒绝工具调用等不支持字段。

### 页面与交互（REQ-003、REQ-009、REQ-013）

| 页面 | 核心任务 | 应有操作与结果 |
| --- | --- | --- |
| 保护 | 确认哪个应用正在接受检查 | 开启、停止、错误处理、最近验证时间；API 接入作为次级操作 |
| 记录 | 核对真实请求发生了什么 | 筛选 / 搜索、原文显隐、替换对照、规则与版本、实际发送结果、清空 |
| 规则 | 决定检查对象与处理动作 | 内置 / 自定义分组、启停、动作、新增 / 编辑 / 删除、按需本地测试 |
| 设置 | 调整运行方式和恢复连接 | 端口、生命周期、必要的上游配置、数据说明、版本与文档入口 |

不增加没有实际对象的工作空间、云端切换和「Local」装饰。长篇研究与实验说明进入仓库；未适配平台不占据日常主要操作。按钮无效、加载不结束或禁用原因不明都属于功能缺陷，不以视觉样式替代修复。

## 本地数据与安全边界

| 数据 | 当前保存方式 | 产品约束 |
| --- | --- | --- |
| 原始请求预览、替换预览、处理记录 | 网关进程内存 | 原文默认隐藏；不默认上传或持久化；清空和退出后释放 |
| 替换映射 | 单请求内存 | 未来扩展会话映射仍默认留在本机，并有明确清理边界 |
| 内置动作覆盖与自定义规则 | 本地配置文件 | 重启保留；规则内容本身也可能敏感，不进入日志与遥测 |
| 原客户端登录与模型 Key | 由原客户端管理；代理逐请求使用必要认证 | 原生接入不复制登录资料；自定义 API 修改原配置时保留其已有 Key |
| 网关中手工填写的 API Key | 当前进程内存 | 不另存到网关文件；不跟随任意重定向发送 |
| CA 与私钥、接入恢复资料 | 本地用户数据目录 | 每台设备独立、最小权限；不上传、不提交仓库；完整撤销按 REQ-011 补齐 |
| 未来团队审计 | 尚未实现 | 默认只考虑必要元数据；原文与映射不作为默认采集对象 |

当前记录最多 100 条、总容量最多 8 MiB；原文与替换预览各最多 24,000 个字符，超长内容保留开头和结尾。检测使用完整的受支持文本字段，预览截断不等于检测截断。本次启动的统计不能解释为长期历史报告。

macOS 当前信任限定到当前用户、`www.workbuddy.ai` 的 SSL 用途；Windows 实现使用当前用户根证书存储，不能宣称具有同等的系统域名限制。代理自身限定解密目标域名。Windows 实际授权与恢复行为仍需真机验收。

本产品不管理原客户端自己的历史、日志或第三方模型服务的数据保留，也不提供操作系统交换内存和崩溃转储的取证级擦除保证。平台认证、限流和账户限制须与本地策略拒绝区分；技术测试通过不能推导长期账号安全或平台认可。

## 技术约束

沿用现有 Electron + React + TypeScript 项目和 mitmproxy 原生运行时。当前需求整理不要求更换技术栈，也不引入新的生产依赖。

已存在的六类接口继续服务于具体能力：`SecretDetector`、`PIIDetector`、`ReversiblePseudonymizer`、`PolicyEngine`、`ProviderRouter`、`SemanticClassifier`。其中语义分类与自动路由仍是预留能力；不能因为接口存在而将对应需求标记完成。

普通 API 与 WorkBuddy 原生 HTTPS 共用规则、策略和记录机制；客户端协议分别适配。域名白名单、协议识别、正文检查、认证保留与会话恢复分别验证。模块与数据流见 [架构说明](ARCHITECTURE.md)，当前端点和运行限制见 [开发指南](DEVELOPMENT.md)。
