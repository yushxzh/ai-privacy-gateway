# 0.1.6：WorkBuddy 一键接入与验收

日期：2026-09-12。验收环境：本机 macOS Apple Silicon、WorkBuddy AI 5.5.2、原登录与 Auto 模型。本轮按用户决定只完成一键接入，语义分类暂缓，Windows 真机验收未进行。

## 本轮完成

| 功能 | 实现 |
| --- | --- |
| 一键开启 | 启动随包代理、检查证书信任、保存原代理设置、正常重启 WorkBuddy |
| 沿用原使用方式 | 不改模型 URL、Key 或登录资料；请求仍发往 WorkBuddy 官方服务 |
| 可见生效状态 | 区分未开启、接入中、已配置、已验证、恢复中和需要处理；真实请求通过校验后才显示已验证 |
| 停止与正常退出 | 先恢复原代理、按需重启 WorkBuddy，再停止代理；恢复失败暂缓退出 |
| 失败恢复 | 端口冲突、授权取消、客户端不退出、启动失败、损坏配置、连续点击均有处理；不强杀 WorkBuddy |
| 原设置保留 | 只备份和修改两个代理字段；保留无关改动和用户后来设置的其他代理 |
| 异常退出后续处理 | TLS 子进程在检查入口失联后自行退出；网关重开根据恢复资料尝试重新接入 |
| 使用文档 | [一键接入、停止、恢复与排错](USAGE.md)，同步 README、MVP 与架构说明 |

本轮未增加 npm 生产依赖。完整安装包附带 mitmproxy 12.2.3 独立运行时，从官方固定版本下载并核对 SHA-256；用户不再需要 Python 或实验启动参数。已有同一 CA 的有效授权会复用。

## 实测发现与修复

首轮恢复测试发现：代理字段虽然恢复，但客户端没有重启，仍持有旧代理配置。WorkBuddy 5.5.2 的实际 macOS 可执行名是 `Electron`，与界面名称不同。修正为按应用包内实际路径识别存活进程后，重启和原连接恢复均通过实测。

另补充连续退出保护：恢复期间重复点击退出不会绕过恢复步骤。损坏代理配置和恢复文件会显示错误，不再将操作留在永久加载状态。
