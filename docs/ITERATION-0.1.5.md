# 0.1.5 交付与验证

日期：2026-09-12。环境：macOS Apple Silicon、WorkBuddy AI 5.5.2、原登录与 Auto 模型。

本轮完成了逐规则动作配置、自定义规则和本地保存，并在真实 WorkBuddy 中验证「替换 → 主动阻断 → 改回替换后重试」。未使用截图里的真实 Token，也未重放截图中的业务接口。

## 问题与修正

旧实现将凭据命中固定为阻断；规则页的「自定义输入」只是试验文本，不能创建真正的过滤规则。0.1.5 将检测结果与处理动作分开，用户可以修改默认策略。

| 用户要求 | 本轮交付 |
| --- | --- |
| 不应见到 Token 就阻断 | 14 条内置规则默认全部为「替换」 |
| 每类敏感信息可以自己选择动作 | 每条内置 / 自定义规则均可选择替换、阻断或关闭，保存后下一条请求生效 |
| 用户自定义规则 | 固定文本 / 正则，新增、编辑、删除、忽略大小写、可选本地测试 |
| 重启后保留 | 内置动作覆盖与用户规则存本机；普通 API 与原生 HTTPS 共用配置 |
| 明确为什么被处理 | 详情记录规则名称、来源、动作和配置版本；阻断详情可直接返回规则设置 |
| 移除 Demo 与无效占位 | 导航收敛为保护、记录、规则、设置；移除日常 Demo、Local / 工作空间及语义分类占位，正反例留在测试代码 |
| 原登录正常使用 | 原服务认证 Header 不扫描、不改写；正文凭据按规则处理 |
| 避免内容阻断显示成登录过期 | 原生内容阻断改为 HTTP 422；真实实测表现为普通服务错误，改回替换后同任务直接重试成功 |

正常有效的 Token 也可能敏感，但识别出 Token 不意味着必须阻断。正文中的 Token 可以换成代号；模型随后无法用该代号执行依赖真实凭据的登录或接口调用。原平台自身的实际认证继续保留。

截图中的「3004 登录过期」不能仅凭截图证明是网关导致。本轮证据证明了新版本的主动阻断与恢复行为，没有据此推断所有认证故障均已解决。
