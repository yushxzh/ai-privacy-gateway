# WorkBuddy 自定义 API 接入

版本 0.1.4，更新于 2026-09-12。自定义来源不限制为 DeepSeek：只要使用 WorkBuddy 的自定义模型配置，并兼容 OpenAI Chat Completions 文本格式，就可按模型启用过滤。内置会员模型保持原连接。

## 操作

1. 在 WorkBuddy「设置 → 模型 → 添加模型」保存原服务 URL、模型 ID 与该服务的 Key。可以使用供应商预设，也可以选「自定义 API」。无认证本地服务可留空 Key。
2. 打开 Privacy Gateway，进入「接入应用 → WorkBuddy」。模型列表显示原来源，逐个点击「启用过滤」。没有已保存的自定义模型时不能启用。
3. App 更新所选模型的接口地址，关闭工具、图片、思考能力，保留原 Key。WorkBuddy 未加载新配置时重启；网络代理保持「直接连接」。
4. 在新任务中选择对应自定义模型，发送内置规则页的合成测试内容。在网关「请求记录」查看来源、动作和原文 / 替换结果。
5. 需要直接访问原服务时，在该模型行点击「恢复直连」。App 恢复原 URL 与先前能力标记；期间由用户改过的其他字段保留。

多个自定义模型分别控制，可以只过滤其中一个。切换到内置模型不会自动经过本产品。新增模型需单独启用；删除模型或将其 URL 改回原服务后，网关自动撤销旧入口。

## 地址和认证

| 项目 | 行为 |
| --- | --- |
| 模型 Key | 仍由 WorkBuddy 管理，网关不要求重新输入、不另存一份 |
| 上游来源 | 绑定到该模型启用时的原 URL，支持不同主机、路径及非凭据查询参数 |
| 本地地址 | 每模型生成独立地址；用按钮复制，界面隐藏随机通行值 |
| App 重启 | 从本机接入资料恢复，地址不因普通重启改变 |
| 原服务改动 | 先恢复直连，在 WorkBuddy 修改并保存，再重新启用过滤 |
| 更换网关端口 | 已接入模型需重新启用以更新本地地址 |
| 无 Key 的本地模型 | 可接入；HTTP 或 HTTPS 来源以 WorkBuddy 已保存配置为准 |

本地恢复资料只包含原 URL、能力标记和本网关连接通行值。API Key、Prompt、替换映射和请求记录不写入该资料。原 URL 不允许包含用户名、密码或密钥查询参数。模型认证随当前请求发送到绑定来源，不跟随重定向。

WorkBuddy 的「自定义协议」开关影响 URL 拼接：关闭时自动补齐 `/chat/completions`，开启时使用完整 URL。这里的「协议」不意味着可自动把 Anthropic、Gemini 等不同 JSON 格式转换为 OpenAI 格式。[WorkBuddy 官方模型文档](https://www.workbuddy.ai/docs/workbuddy/From-Beginner-to-Expert-Guide/Function-Description/Model)

## 验证和限制

- 所有 14 条规则与网关使用同一检测引擎。凭据命中后阻断；邮箱、手机号、身份证格式、明确账号字段替换为代号。
- 本地 HTTP 用例验证不同模型名称、不同来源路径、带查询参数的自定义地址、有 / 无 Key、来源隔离、替换和阻断。配置用例覆盖 OpenAI、千问、本地模型与自定义代理 URL；不等同于这些商业服务全部完成真实 Key 联调。
- DeepSeek 已用真实 WorkBuddy 5.5.2 验证主对话、多轮文本与凭据阻断，历史请求证据见 [0.1.3 联调记录](WORKBUDDY-DEEPSEEK.md)。本轮新版实际验证见 [验证记录](VALIDATION.md)。
- 当前仅文本：实际工具调用、工具结果、图片、开启思考及未知协议字段会被拒绝；不能用于完整编码 Agent 流程。
- 流式回复保留代号；不会跨请求关联同一实体，非流式 JSON 可恢复当前请求代号。
- WorkBuddy 可能将网关的 `403 privacy_blocked` 显示为「鉴权失败」。若网关记录显示「阻断」，无需因此更换 Key。
- 仅保护实际经过本网关的模型请求。内置模型、客户端遥测、插件和其他网络访问不在此路径内。

旧版 0.1.3 只支持固定 DeepSeek 入口；首次升级若尚无恢复资料，需要点击一次「启用过滤」。该迁移仅识别旧版明确的 DeepSeek 模型，其余缺少原来源的模型需先在 WorkBuddy 恢复原 URL。
